## Overview

**Page Purpose:** Lista curada de funcionalidades em linguagem pastoral, NAO bullet list corporativa. Cada feature e apresentada como resposta a uma tensao pastoral real. Screenshot/mockup por feature. Zero video auto-play. Julia valida que o produto faz o que ela precisa.

**User Situation:** Domingo 21h47 (sessao 1 mobile) ou segunda de manha (sessao 2 desktop). Julia quer ver "como funciona" apos ler o manifesto.

**Success Criteria:** Julia entende as 4-5 funcionalidades core em ≤3 minutos e sente que cada uma resolve uma tensao real que ela conhece.

**Route:** `/funcionalidades` — SSR/SSG, publica.

| # | Tension (PT-BR) | Title Key | Title (PT-BR) | Description Key | Description (PT-BR) |

| 1 | "Faz 2 semanas que o Pedro nao aparece. Vale uma mensagem?" | `features.radar.title` | "Radar Pastoral" | `features.radar.desc` | "Sinais que ajudam a lembrar quem precisa de uma conversa. Sem pontuacao, sem ranking — so visibilidade humilde." |

## Technical Notes

- **Rendering:** SSR/SSG. Images lazy-loaded. Screenshots como `<img>` otimizadas (WebP, srcset).
- **Screenshots:** Mockups/wireframes do produto (nao screenshots finais ate o produto existir). Briefing: mostrar a tela real, nao render 3D corporativo.
- **Performance:** TTI ≤2s. Images below fold lazy-loaded.
- **Content:** Feature list e curada — 4-5 features max no MVP. Sem "E mais..." generico.
