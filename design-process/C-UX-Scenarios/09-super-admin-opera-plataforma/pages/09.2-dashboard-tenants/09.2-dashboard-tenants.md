## Overview

**Page Purpose:** Lista paginada de todos os tenants da plataforma. Metadata operacional apenas — nome, slug, plano, status, membros (count), data de criacao. Zero dados pastorais. Paulo verifica saude geral, busca por nome, filtra por status/plano, e navega para detalhe ou provisionamento.

**User Situation:** Segunda de manha. Paulo fez login + MFA. Dashboard aparece. Ele quer: (1) verificar se ha `provisioning_failed` pendente, (2) buscar "Restauracao" para confirmar que nao existe duplicata, (3) clicar "Novo Tenant" para provisionar.

**Success Criteria:** Em ≤15 segundos, Paulo tem visao geral de todos os tenants e pode agir (filtrar, buscar, provisionar, detalhar).

**Entry Points:**
- (1) Redirect pos-login/MFA (09.1)
- (2) Sidebar navigation (retorno)

**Exit Points:**
- (1) "Novo Tenant" → 09.3
- (2) Click em row → 09.4
- (3) Sidebar navigation → outras telas admin

**Route:** `/app/admin/super/tenants` — rota protegida, guard `@Roles('super_admin')`.

## Technical Notes

- **Rendering:** CSR — rota protegida `/app/admin/super/tenants`. Guard server-side `@Roles('super_admin')`.
- **API:** `GET /api/v1/admin/super/tenants` → paginated response. Query params: `page`, `limit`, `status`, `plan`, `search`, `sortBy`, `sortOrder`.
- **PrismaAdminService:** Connection pool separado sem RLS. Acessa tabela `tenants` diretamente. Retorna apenas metadata (name, slug, plan, status, createdAt, memberCount como aggregate).
- **Zero pastoral data:** Endpoint NAO retorna care_actions, meeting_reflections, radar_signals, nem dados de participantes individuais. `memberCount` e o unico aggregate de pessoas — count, nao nomes.
- **Accessibility:** WCAG AA. Table com `role="grid"`. Sortable headers com `aria-sort`. Rows focusable via Tab.
