## Overview

**Page Purpose:** Login padrao (`/login`) seguido de challenge MFA obrigatorio (TOTP). O Super Admin e o unico role com MFA obrigatorio (Story 2.3). Apos email/senha + TOTP, ExperienceResolver detecta `super_admin` → redirect para `/app/admin/super/tenants` (09.2).

**Why specified-light:** A tela de login e existente (cenarios 01, 03, 06, 07). O challenge TOTP e renderizado pelo Keycloak (conditional authentication flow). Nao ha UI nova no produto — apenas a configuracao do Keycloak para exigir MFA.

---

## Auth Flow

```
[/login — email + senha]
    |
    ├── Keycloak valida credenciais
    │
    └── Keycloak detecta role super_admin
        │
        └── Conditional auth flow: TOTP required
            │
            ├── Tela TOTP (Keycloak-rendered)
            │   "Digite o codigo do seu autenticador"
            │   [______] (6 digitos)
            │   [Verificar]
            │
            ├── Codigo valido → JWT com role super_admin
            │   → ExperienceResolver → /app/admin/super/tenants (09.2)
            │
            └── Codigo invalido → "Codigo incorreto. Tente novamente."
                (max 3 tentativas → lockout 5 min)
```

**Design decision:** MFA via Keycloak conditional auth flow, nao via UI custom. O produto nao renderiza a tela TOTP — o Keycloak cuida disso. Menos superficie de ataque, menos codigo custom.

---

## MFA Setup (First-time)

Na primeira vez que Paulo faz login apos receber role `super_admin`, o Keycloak exige configuracao do TOTP:

1. Keycloak mostra QR code para Google Authenticator / Authy
2. Paulo escaneia e digita codigo de verificacao
3. TOTP configurado — proximos logins pedem apenas o codigo

**Nota:** setup acontece no Keycloak, fora do produto. Nao requer spec de UI.

---

## Routing Post-Auth

```
ExperienceResolver:
    │
    ├── Role: super_admin → /app/admin/super/tenants (09.2)
    │   (NÃO passa por seleção de igreja — Super Admin é cross-tenant)
    │
    ├── Role: admin_tenant → /app/admin/ (03.2)
    ├── Role: leader → /app/gestao/radar (01.2)
    └── Role: participant → /app/consumo/grupos (06.4)
```

**Design decision:** Super Admin nao ve tela de selecao de igreja (08.2). Ele opera cross-tenant — nao pertence a nenhum tenant especifico. O ExperienceResolver redireciona diretamente para o dashboard operacional.

**DDR resolved (parcial):** Rotas de Super Admin vivem sob `/app/admin/super/*`, separadas das rotas de Admin Tenant (`/app/admin/*`). Guard `@Roles('super_admin')` no route group.

---

## Technical Notes

- **Keycloak:** Conditional authentication flow com TOTP required para role `super_admin`. Story 2.3.
- **TOTP providers:** Google Authenticator, Authy, 1Password, qualquer app TOTP RFC 6238.
- **Lockout:** 3 tentativas falhadas → lockout 5 min (Keycloak brute force detection).
- **JWT:** Token inclui role `super_admin`. Nao inclui `tenant_id` (cross-tenant).
- **Accessibility:** Keycloak theme herda WCAG AA do tema customizado.
