## Overview

**Page Purpose:** Pagina de detalhe de um tenant especifico. Mostra metadata operacional completa (nome, slug, plano, status, data de criacao, admin designado, contagem de membros/grupos). Acoes: editar nome, mudar status (suspender/reativar), retry provisioning (se falhou). Zero dados pastorais.

**User Situation:** (A) Paulo acabou de provisionar "Igreja Restauracao" — redirect automatico para ca. Verifica que tudo esta correto e fecha. (B) Paulo clicou numa row do dashboard — quer verificar detalhes de um tenant existente.

**Success Criteria:** Paulo ve todas as informacoes operacionais relevantes e pode agir (editar, suspender, retry) em ≤10 segundos.

**Entry Points:**
- (1) Redirect pos-saga sucesso (09.3)
- (2) Click em row do dashboard (09.2)

**Exit Points:**
- (1) "← Voltar" → 09.2
- (2) Sidebar navigation

**Route:** `/app/admin/super/tenants/{id}` — rota protegida, guard `@Roles('super_admin')`.

## Technical Notes

- **Rendering:** CSR — rota protegida `/app/admin/super/tenants/{id}`. Guard `@Roles('super_admin')`.
- **API:** `GET /api/v1/admin/super/tenants/{id}` → tenant metadata + aggregates (memberCount, groupCount, leaderCount).
- **Edit:** `PATCH /api/v1/admin/super/tenants/{id}` → `{ name }`. Inline edit, nao formulario separado.
- **Suspend:** `PATCH /api/v1/admin/super/tenants/{id}` → `{ status: "suspended" }`. Backend: invalida sessions Keycloak, marca tenant como suspended. Dados preservados (nao deletados).
- **Reactivate:** `PATCH /api/v1/admin/super/tenants/{id}` → `{ status: "active" }`. Backend: reativa tenant. Usuarios podem logar novamente.
- **Retry:** `POST /api/v1/admin/super/tenants/{id}/retry` → re-executa saga (mesma logica da 09.3).
- **PrismaAdminService:** Aggregates calculados via COUNT queries sem RLS. Nao retorna dados individuais de membros.
- **Domain events:** `tenant.status_changed` com `{ tenantId, oldStatus, newStatus, changedBy }`.
- **Invite status:** Calculado a partir do `user_tenants` + `users` table (invited, sent, accepted).
