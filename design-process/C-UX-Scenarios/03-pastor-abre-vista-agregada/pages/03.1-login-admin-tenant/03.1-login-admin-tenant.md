## Overview

**Page Purpose:** Autenticação do Admin Tenant (role RBAC do Pastor Titular). Fluxo idêntico ao 01.1 do líder — mesmo Keycloak, mesmos Stories (2.1, 2.2). A diferença é o redirect pós-auth: RBAC detecta `Admin Tenant` → `/app/admin/` (experiência consolidada de administração, UX-DR22 a 25).

**User Situation:** Domingo, 14h20. Pastor no notebook, escritório da igreja. Abre o navegador, digita URL ou usa bookmark. Sessão pode estar persistente (cookie Keycloak válido → redirect transparente <1s). Se expirada → tela de login padrão.

**Success Criteria:** Autenticação transparente. Se sessão ativa → redirect imediato para 03.2. Se login necessário → ≤30s para completar.

**Why specified-light:** Login é infraestrutura implementada (Stories 2.1/2.2, Epic 2). Tela de login compartilhada com todos os roles — especificada uma vez, reutilizada. A diferença está apenas no redirect pós-auth via ExperienceResolver.

---

## Auth Flow

```
[Abre navegador] → /login
   │
   ├── Sessão Keycloak ativa?
   │   ├── SIM → ExperienceResolver detecta role
   │   │         ├── Admin Tenant → /app/admin/ → 03.2
   │   │         ├── Líder → /app/gestao/radar → cenário 01
   │   │         └── Participante → /app/consumo/ → cenário 06
   │   └── NÃO → Tela de login (email/senha · Google OAuth)
   │             └── Auth OK → ExperienceResolver → redirect por role
   │
   └── Token inválido / expirado → Tela de login
```

---

## ExperienceResolver — Redirect por Role

| Role RBAC | Experiência | Rota base | Decisão |
|-----------|-------------|-----------|---------|
| Admin Tenant | Administração | `/app/admin/` | UX-DR22 — 3 experiências consolidadas |
| Líder | Gestão pastoral | `/app/gestao/` | UX-DR23 |
| Participante | Consumo | `/app/consumo/` | UX-DR24 |
| Super Admin | Operação | `/app/ops/` | UX-DR25 |

**Nota:** O pastor (Admin Tenant) é redirecionado para `/app/admin/`, que inclui a sub-rota `/app/admin/igreja/vista` (vista agregada). A home do admin pode ser a própria vista agregada ou um hub — decisão de Phase 4 da área admin.

## Page States

| State | When | Behavior |
|-------|------|----------|
| **Redirect transparente** | Sessão Keycloak ativa + role válido | <1s → redirect silencioso para `/app/admin/` |
| **Login necessário** | Sem sessão ou sessão expirada | Tela de login padrão (email/senha + Google OAuth) |
| **Login erro** | Credenciais inválidas | Mensagem inline "Email ou senha incorretos" |
| **MFA** | Se habilitado (pós-MVP) | Fluxo Keycloak nativo |

---

## Technical Notes

- **Rendering:** SSR (rota pública `/login`).
- **Auth:** Keycloak com fluxo unificado — Stories 2.1 (email/senha), 2.2 (Google OAuth).
- **ExperienceResolver:** Middleware Next.js que lê roles do token Keycloak e redireciona. Implementação definida no Epic 2.
- **Sessão persistente:** Cookie Keycloak com refresh token. Desktop tende a manter sessão mais longa (configuração Keycloak por client).
- **Desktop layout:** Mesmo design visual do login mobile, com mais whitespace. Content max-width 480px centralizado (reutiliza OnboardingPageLayout do cenário 05).
