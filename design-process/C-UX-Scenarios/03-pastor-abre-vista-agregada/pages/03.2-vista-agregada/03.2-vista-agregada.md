## Overview

**Page Purpose:** Resumir a saúde pastoral dos grupos da igreja em linguagem humana. Em 5 minutos, o pastor identifica 1–2 grupos que merecem atenção — não por métrica ruim, mas por sinal relacional. Não é dashboard analítico, não tem gráficos, não tem ranking. É uma vista pastoral: "como estão meus grupos esta semana?"

**User Situation:** Domingo, 14h20. Pastor no notebook, escritório da igreja, 30 minutos de quieto. Acabou de autenticar (03.1). Vê os 12 grupos da igreja em cards com status pastoral qualitativo. Quer sair dessa tela sabendo: "tenho 1 ou 2 grupos que merecem minha atenção essa semana."

**Success Criteria:** Em ≤5 minutos, pastor identifica 0–2 grupos que merecem conversa com o líder. Zero comparação entre líderes. Zero pontuação numérica. O tom é "como estão meus grupos", não "quem está performando mal".

**Entry Points:**
- (1) Redirect pós-login via ExperienceResolver (03.1)
- (2) AdminSidebar → "Vista da Igreja"
- (3) Deep link `/app/admin/igreja/vista`

**Exit Points:**
- (1) Toque num card → 03.3 Drill-down Grupo
- (2) AdminSidebar → outras áreas admin
- (3) Logout

**Route:** `/app/admin/igreja/vista`

## Reference Materials

**Strategic Foundation:**
- Epic 6 FR60 — Vista agregada do tenant (⚠️ condicionada à promoção para 1a-beta)
- Cenário 03 outline — Tone audit, anti-patterns, release gate
- Design Implication A — Radar humilde invertido ao pastor

**Design Constraints:**
- **Densidade invertida:** desktop permite mais contexto textual por card, mas nunca ranking
- **Linguagem qualitativa:** status é frase humana, nunca pontuação 0–100
- **Improviso Sagrado:** sistema mostra contexto, nunca sugere ação
- **Privacidade:** pastor vê o que líderes registraram, nunca dados brutos de participação
- NFRs: TTI ≤2s, WCAG AA
- Glossário banido: monitorar, rastrear, frequência, célula, relatório, dashboard, rebanho, score, ranking, KPI, engajamento

- **Sem contagem nos filtros** — evita que vire "3 vermelhos, 5 amarelos" → mentalidade de KPI.

#### Status Pastoral (sistema qualitativo)

| Status | Dot | Border Color | Phrase (PT-BR) | Translation Key | Condition |
|--------|-----|-------------|----------------|-----------------|-----------|
| Saudável | 🟢 | `border-green-500` | "Conversa saudável esta semana" | `vista.status.healthy` | Reunião + reflexão registrada + sem sinais 🔴 |
| Vale acompanhar | 🟡 | `border-yellow-500` | "Vale acompanhar" | `vista.status.attention` | ≥1 sinal 🟡 no radar do líder, ou sem reunião há 2+ semanas |
| Vale uma ligação | 🔴 | `border-red-400` | "Pastor, vale uma ligação" | `vista.status.call` | ≥1 sinal 🔴 no radar do líder, ou sem atividade há 3+ semanas |
| Sem sinal | ⚪ | `border-gray-300` | "Sem sinal esta semana" | `vista.status.noSignal` | Nenhuma reunião ou registro nesta semana |

**Design decisions:**
- **Frases humanas, nunca pontuação** — "Vale acompanhar" em vez de "Score: 65/100"
- **Vermelho suave (red-400)** — não é alarme, é convite gentil. "Pastor, vale uma ligação" não é "URGENTE"
- **"Sem sinal" é neutro** — grupo pode estar de recesso, feriado, líder viajando. Não é falha.
- **Cor redundante com texto** — WCAG AA: dot + border-left + frase. Nunca só cor.
- **Ordenação ≠ ranking** — a lista não é "do pior ao melhor". É "do que pode precisar de atenção ao que está bem"
- **Backend calcula status** — agregação de sinais do radar + registros do líder. Recalculado 1x/dia, não em tempo real.

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/admin/`).
- **Data fetching:** TanStack Query — GET `/api/v1/admin/church/overview` → 200. Response: `{ data: GroupCard[], meta: { lastCalculated, groupCount } }`. `staleTime: 5min` (cadência semanal do pastor, não precisa de real-time).
- **Status calculation:** Backend job (BullMQ) roda 1x/dia. Agrega sinais do radar de cada líder (Epic 6 FR54–59) + registros de reunião (Epic 5). Resultado salvo em tabela `group_pastoral_status` com `tenant_id` + RLS.
- **Ordering:** Backend retorna cards já ordenados por `attention_level` DESC. Frontend não reordena.
- **Multi-tenancy:** `tenant_id` via AsyncLocalStorage. Admin Tenant só vê grupos do próprio tenant.
- **FR60 dependency:** Esta página materializa FR60 (vista agregada do tenant). ⚠️ Condicionada à promoção para Release 1a-beta.
- **Accessibility:** WCAG AA. Cards como `role="article"` dentro de grid `role="list"`. Filter pills como `role="radiogroup"`. Status com cor + texto + dot (tripla redundância). Keyboard navigation completa.
