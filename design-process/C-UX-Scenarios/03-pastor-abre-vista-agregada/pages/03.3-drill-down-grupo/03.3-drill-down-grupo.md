## Overview

**Page Purpose:** Entender o contexto pastoral de um grupo específico nas últimas 2 semanas — não como gráfico ou série histórica, mas como narrativa temporal construída a partir dos registros do próprio líder. O pastor lê, entende a dinâmica, e decide se quer conversar com o líder desse grupo.

**User Situation:** Domingo, 14h25. Pastor clicou num card da vista agregada (03.2) — o Grupo Vida Nova está com status "Vale acompanhar". Ele quer entender: o que aconteceu nesse grupo nas últimas 2 semanas? O líder registrou alguma reflexão? Tem alguém com sinal no radar? O contexto suficiente para decidir: "vale eu ligar para o João (líder) esta semana?"

**Success Criteria:** Em ≤3 minutos, pastor entende o contexto do grupo e decide: (a) conversar com o líder → 03.4, ou (b) voltar à vista → 03.2. Nenhuma ação obrigatória nesta tela.

**Entry Points:**
- (1) Toque num GroupCard na 03.2
- (2) Deep link `/app/admin/igreja/grupos/{groupId}`

**Exit Points:**
- (1) "Ver o líder desse grupo" → 03.4
- (2) Back → 03.2 Vista Agregada
- (3) AdminSidebar → outras áreas

**Route:** `/app/admin/igreja/grupos/{groupId}`

## Reference Materials

**Strategic Foundation:**
- Epic 6 FR60 — Vista agregada (drill-down por grupo)
- Cenário 02 — Reflexões `meeting.reflection` do líder são o conteúdo principal aqui
- Cenário 01 — Sinais do radar do líder alimentam a narrativa

**Design Constraints:**
- **Narrativa, não gráfico:** zero série histórica, zero tendência numérica no MVP
- **O que o líder registrou, não telemetria:** pastor lê reflexões e sinais, não dados brutos de participação
- **Improviso Sagrado:** sistema mostra contexto, nunca "ligue para o líder"
- **Privacidade do participante:** nomes de participantes visíveis ao pastor (ele é Admin Tenant), mas status de presença individual NÃO exposto — apenas agregado
- NFRs: TTI ≤2s, WCAG AA
- Glossário banido: monitorar, rastrear, frequência, célula, relatório, dashboard, rebanho, score, ranking, KPI

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/admin/`).
- **Data fetching:** TanStack Query — GET `/api/v1/admin/church/groups/{groupId}/timeline` → 200. Response: `{ data: { group: GroupHeader, entries: TimelineEntry[] }, meta: { windowStart, windowEnd } }`. `staleTime: 5min`.
- **Timeline entries:** Aggregation no backend de 2 fontes: (1) `meeting_reflections` (cenário 02), (2) `care_actions` (cenário 01). Unified timeline sorted by date DESC.
- **Presence aggregation:** Backend retorna apenas contagem (`present: 6, total: 8`), nunca nomes individuais para esta view. Nomes individuais só são visíveis ao líder do grupo, não ao Admin Tenant nesta tela.
- **Multi-tenancy:** `tenant_id` via AsyncLocalStorage. groupId validado contra tenant do Admin Tenant.
- **Accessibility:** WCAG AA. Timeline entries como `role="article"` dentro de `role="feed"`. Blockquotes com `cite` acessível. Back link com `aria-label`.
