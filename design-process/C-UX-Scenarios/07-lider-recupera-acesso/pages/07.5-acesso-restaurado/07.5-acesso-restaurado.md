## Overview

**Page Purpose:** Confirmação implícita de que o acesso foi restaurado. Não é uma tela nova — é o redirect automático para a tela principal do líder (01.2 Radar Pastoral) após o reset de senha bem-sucedido. O Marcos vê o radar como sempre. O ciclo da quarta de manhã foi recuperado.

**Why specified-light:** Não há UI nova. O redirect é transparente: 07.4 salva senha → auto-login → ExperienceResolver → `/app/gestao/radar` (01.2). O cenário 07 termina onde o cenário 01 começa.

---

## Redirect Flow

```
[07.4 — "Salvar e entrar" success]
    │
    ├── Backend: Keycloak reset password + create session
    ├── Response: JWT cookies set
    │
    └── Frontend: redirect → ExperienceResolver
        │
        ├── Role: Líder → /app/gestao/radar (01.2)
        ├── Role: Admin Tenant → /app/admin/ (03.2)
        ├── Role: Participante → /app/consumo/grupos (06.4)
        └── Role: Super Admin → /app/ops/
```

**Design decision:** O redirect é por role — password recovery funciona para todos os roles (FR83 cobre todos). Cada role volta para sua experiência consolidada.

---

## Success Confirmation

Não há toast, banner, ou mensagem de "Senha redefinida com sucesso". O Marcos vê o radar — **essa é a confirmação**. Ele sabe que funcionou porque está vendo o que queria ver.

**Design decision:** Silêncio como confirmação. Marcos está com pressa (6h17 na quarta de manhã). Não precisa de celebração — precisa do radar. Consistente com tom seco do 01.5 ("Guardei.") e do 03.4 ("Anotado.").

## Technical Notes

- **Auto-login:** Após reset, backend cria sessão via Keycloak token exchange. JWT cookies setados na response do POST da 07.4.
- **ExperienceResolver:** Middleware Next.js que lê role do token e redireciona. Mesmo middleware usado em 01.1, 03.1, 06.3.
- **Metric:** `recovery_to_radar_time` = timestamp entre `auth.recovery.started` e primeiro pageview pós-recovery. Target: ≤3 min.
