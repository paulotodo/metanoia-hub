## Overview

**Page Purpose:** Landing pós-clique do email. Confirma que a Juliana está no lugar certo: mostra o nome do líder, o nome do grupo, e convida a autenticar. Zero formulário visível antes de escolher o método de auth. Zero campo de perfil. É um tapete de boas-vindas personalizado.

**User Situation:** Terça, 19h45. Juliana tocou "Confirmar presença no grupo" no email. Chrome abre. Ela vê o nome do Marcos e o nome do grupo. Precisa decidir em 4 segundos: "continuo ou fecho?"

**Success Criteria:** Em ≤4 segundos, Juliana reconhece o convite do Marcos e toca em "Continuar com Google". Zero campo preenchido. Zero surpresa.

**Entry Points:**
- (1) Toque no CTA do email (06.1) — caminho primário
- (2) Colagem direta da URL `/convite/{token}`

**Exit Points:**
- (1) "Continuar com Google" → 06.3 OAuth Google
- (2) "Usar email e senha" → fluxo auth email/senha (fora do sunshine path)
- (3) Fechar aba (abandono — token permanece válido 7 dias)

**Route:** `/convite/{token}` — rota pública, SSR, sem autenticação.

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | Token válido, dados do líder carregados | Layout completo com avatar + mensagem | Google, email, terms |
| **Loading** | Resolvendo token (SSR) | Logo + skeleton | Nenhuma |
| **Token expired** | Token >7 dias | Mensagem pastoral + instruções | Link para contatar líder |
| **Token used** | Token já aceito | Mensagem + link para login | Login |
| **Token invalid** | Token malformado | Mesma aparência de expired | — |
| **Error (network)** | Falha ao resolver token | Mensagem + retry | Retry |

## Technical Notes

- **Rendering:** SSR — rota pública, Next.js route group `(public)`.
- **Token resolution:** GET `/api/v1/invites/{token}/resolve` → 200. Response: `{ leaderName, leaderAvatarUrl?, groupName }`. Zero dado sensível.
- **Auth flow:** Ao tocar Google → OAuth redirect com `state` contendo token de convite. Pós-auth, backend associa participante ao grupo automaticamente.
- **Auto-accept:** Se sessão Keycloak já ativa, o convite é aceito automaticamente (POST `/api/v1/invites/{token}/accept`) e redirect para 06.4.
- **Performance:** SSR com TTI ≤1.5s (página leve). Avatar lazy-loaded.
- **Accessibility:** WCAG AA. Botões com texto descritivo. Focus ring visível. Mensagem de convite como H1 para screen readers.
- **Nota de reutilização:** Esta tela é similar à 05.1 (Aceite do Convite admin), mas com diferenças: (1) mostra avatar do líder, (2) auth buttons em vez de "Aceitar e começar", (3) tom pastoral ao participante vs. tom profissional ao admin.
