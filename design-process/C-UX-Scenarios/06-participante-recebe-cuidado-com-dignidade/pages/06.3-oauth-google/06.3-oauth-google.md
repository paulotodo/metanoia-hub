# 06.3 OAuth Google

---

## Overview

**Page Purpose:** Autenticação via Google em 2 toques. Tela controlada pelo Google, não pelo produto. Juliana seleciona sua conta e toca "Continuar". ~6 segundos.

**User Situation:** Juliana tocou "Continuar com Google" na 06.2. Google mostra a tela de consentimento padrão. Juliana já tem a conta logada no celular — seleciona e continua.

**Success Criteria:** ≤6 segundos. Zero fricção. Redirect automático de volta ao produto.

**Why specified-light:** Tela 100% controlada pelo Google. O produto controla apenas: (1) o nome exibido ("metanoia-hub"), (2) os scopes solicitados (nome + email), (3) o redirect URI.

---

## OAuth Configuration

| Property | Value |
|----------|-------|
| **App name** | "metanoia-hub" |
| **Scopes** | `openid`, `email`, `profile` (nome + email, mínimo necessário) |
| **Redirect URI** | `{baseUrl}/api/auth/callback/google` |
| **State parameter** | Contém token de convite (para auto-aceite pós-auth) |
| **Consent screen text** | "metanoia-hub quer acessar seu nome e email" (controlado pelo Google) |

---

## Flow

```
[06.2 — Toque "Continuar com Google"]
    │
    ├── Google Account Picker (se múltiplas contas)
    │   └── Juliana seleciona a conta dela
    │
    ├── Google Consent Screen
    │   └── "metanoia-hub quer acessar seu nome e email"
    │   └── Juliana toca "Continuar"
    │
    └── Redirect → produto
        │
        ├── Conta nova → Keycloak cria user (role Participante) + aceita convite + redirect 06.4
        └── Conta existente → Keycloak autentica + aceita convite (se pendente) + redirect 06.4
```

---

## Edge Cases

| Case | Behavior |
|------|----------|
| **Juliana nega permissão** | Redirect de volta à 06.2 com mensagem: "Precisamos do seu nome e email para te identificar no grupo." |
| **Juliana não tem Google account** | Usa "Usar email e senha" na 06.2 (fallback, fora do sunshine) |
| **Erro de OAuth** | Redirect à 06.2 com mensagem genérica + retry |
| **Token expirado durante OAuth** | Pós-auth → backend tenta aceitar convite → falha → redirect à 06.2 com "Convite venceu" |

---

## Technical Notes

- **Keycloak integration:** Google OAuth via Identity Provider configurado no Keycloak (Story 2.2, já mergeada).
- **User creation:** Se email novo, Keycloak cria user com role `Participante` automaticamente. Zero campo adicional solicitado.
- **Invite acceptance:** Pós-auth callback, backend lê `state` parameter → POST `/api/v1/invites/{token}/accept` → vincula participante ao grupo.
- **Domain event:** `participant.invite.accepted` disparado no momento do aceite.
