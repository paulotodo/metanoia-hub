## Overview

**Page Purpose:** Tela de login existente (`apps/web/app/(public)/login/page.tsx`). Nenhuma adição visual — a mudança é no **redirect pós-auth**: se `user_tenants.count > 1`, o ExperienceResolver redireciona para `/selecionar-igreja` (08.2) em vez de ir direto para a experiência consolidada.

**Why specified-light:** Zero UI nova na tela de login. A mudança é puramente de routing logic no middleware pós-autenticação.

---

## Routing Logic (Post-Auth)

```
[Login — auth bem-sucedida]
    │
    ├── user_tenants.count == 1
    │   └── Auto-select → ExperienceResolver → experiência por role
    │       ├── Líder → /app/gestao/radar (01.2)
    │       ├── Admin Tenant → /app/admin/ (03.2)
    │       ├── Participante → /app/consumo/grupos (06.4)
    │       └── Super Admin → /app/ops/
    │
    └── user_tenants.count > 1
        └── Redirect → /selecionar-igreja (08.2)
```

**Design decision:** Auto-select para 1 tenant (Story 2.5 AC #3) garante que usuários com 1 igreja nunca veem a tela de seleção. Zero atrito adicionado para o caso comum.

---

## Technical Notes

- **Existing code:** `apps/web/app/(public)/login/page.tsx` (~130 linhas) — sem alteração.
- **Middleware:** ExperienceResolver precisa de um branch adicional: verificar `user_tenants.count` antes de resolver role. Se >1, redirect para `/selecionar-igreja`.
- **Story 2.5 AC #3:** "If user belongs to only one tenant, auto-select and skip."
- **JWT:** O token JWT pós-auth NÃO contém `tenant_id` fixo — contém `user_id` e lista de `tenant_ids` associados. O `tenant_id` ativo é definido na seleção (08.2) e persistido em cookie/session.
