## Overview

**Page Purpose:** Tela de seleção de igreja pós-login. Aparece quando `user_tenants.count > 1`. Cartões com nome da igreja, role do usuário naquela comunidade, e última visita. Marcos toca no cartão da igreja desejada → `tenant_id` é setado → redirect para experiência por role.

**User Situation:** Quarta, 6h15. Marcos fez login. O app detectou 2 igrejas associadas. Marcos precisa escolher "Igreja Vida Nova" para ver o radar da quarta de manhã. ≤3 segundos nesta tela.

**Success Criteria:** Em ≤3 segundos, Marcos toca na igreja certa e é redirecionado para o radar com dados isolados daquela comunidade.

**Entry Points:**
- (1) Redirect pós-login quando `user_tenants.count > 1` (08.1)
- (2) Redirect pós-recovery quando `user_tenants.count > 1` (07.5 → aqui)

**Exit Points:**
- (1) Toque no cartão → set tenant_id → ExperienceResolver → experiência por role (08.4)

**Route:** `/selecionar-igreja` — rota autenticada, sem tenant_id no RequestContext.

**DDR resolved:** Rota `(auth)/selecionar-igreja` — estado intermediário pós-auth, pré-experience. Requer autenticação mas NÃO requer tenant_id (porque é justamente o momento de escolher).

## Reference Materials

**Strategic Foundation:**
- FR03 — Multi-tenant association
- FR10 / Story 2.5 — Tenant selection on access (Release 1a, Sprint 3)
- Story 2.6 — RLS isolation

**Design Constraints:**
- **≤3s** — tempo máximo na tela de seleção
- **Cartões, não dropdown** — cada igreja merece presença visual completa
- **Role visível em linguagem pastoral** — "Você lidera aqui", não "Role: Líder"
- **Última visita** — contexto temporal para decidir (opcional, só se houver dado)
- **Vocabulário:** "comunidade" ou "igreja" user-facing, nunca "tenant"
- NFRs: TTI ≤2s, WCAG AA

## Technical Notes

- **Rendering:** SSR — rota autenticada `/selecionar-igreja`. Middleware Next.js valida JWT mas NÃO injeta tenant_id no RequestContext.
- **API:** GET `/api/v1/auth/my-tenants` → lista de tenants do usuário com role e lastVisit. Não filtra por tenant_id (consulta `user_tenants` sem RLS de tenant).
- **Select:** POST `/api/v1/auth/select-tenant` → body: `{ tenantId }` → valida associação → set `tenant_id` em cookie HttpOnly → 200.
- **ExperienceResolver:** Após set do tenant_id, resolve role do usuário naquele tenant e redireciona para experiência consolidada.
- **Order:** MRU (Most Recently Used) — campo `last_accessed_at` na tabela `user_tenants`.
- **Role labels:** Mapeamento role → frase pastoral feito client-side com translation keys.
- **Accessibility:** WCAG AA. Cards como `role="button"`. Focus visible. Tab navigation.
- **Domain event:** `tenant.selected` com `{ tenantId, userId, source: "login" }`.
