## Overview

**Page Purpose:** A sala LiveKit está aberta. Presença é capturada automaticamente por webhooks. O líder guarda o celular e conduz o encontro. Esta tela só é consultada se: (a) alguém não conseguiu entrar, ou (b) é hora de encerrar. UI minimalista — o celular não compete com o momento relacional.

**User Situation:** Quinta, 20h. Reunião começando. O líder acabou de abrir a sala (02.1). Cada participante conecta pelo próprio celular. O líder coloca o telefone com a tela para baixo. A sala roda em background. 1h30 depois, o líder pega o celular e toca "Encerrar sala".

**Success Criteria:** Zero interação necessária durante a reunião. Se consultada (edge case), a tela mostra em ≤3 segundos quem está na sala. "Encerrar sala" é o único CTA — toque de 56dp, impossível de errar.

**Entry Points:**
- (1) "Abrir sala" na 02.1 (criação bem-sucedida)
- (2) "Entrar na sala" na 02.1 (retomada de sala ativa)
- (3) Deep link `/app/gestao/reunioes/{meetingId}/sala`

**Exit Points:**
- (1) "Encerrar sala" → 02.3 Pós-reunião
- (2) Tabs → navegação lateral (sala continua ativa em background)

**Route:** `/app/gestao/reunioes/{meetingId}/sala`

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/`).
- **LiveKit integration:** Líder se conecta à sala via `livekit-client` SDK. Room token obtido na 02.1 (ou re-obtido via GET `/api/v1/meetings/{id}/room`).
- **Presence pipeline:** LiveKit webhooks → Redis → BullMQ → PostgreSQL. Registra `participant_joined`, `participant_left` com timestamps. Presença integral/parcial calculada no backend.
- **Real-time updates:** `ParticipantConnected` / `ParticipantDisconnected` events do LiveKit client SDK atualizam a lista localmente. Fallback: polling a cada 30s.
- **End room:** POST `/api/v1/meetings/{meetingId}/room/end` → 200. Backend fecha room no LiveKit, webhook `room_finished` processa presença final.
- **Background operation:** Sala continua ativa mesmo com tela bloqueada ou app em background (WebSocket mantém conexão no PWA). Audio/video não são usados no MVP — apenas presença por conexão.
- **Multi-tenancy:** `tenantId` via AsyncLocalStorage. Room scoped por tenant + meeting.
- **Accessibility:** WCAG AA. Dot pulsante tem `aria-label` "sala ativa". Lista de participantes como `role="list"`. Dialog com focus trap.
