## Overview

**Page Purpose:** Mostrar ao líder o *porquê* daquele sinal — o que o sistema observou e o que *não* observou — em linguagem pastoral, sem jargão técnico, sem imperativo automatizado. O líder entende o contexto antes de decidir se e como agir.

**User Situation:** Líder acabou de tocar num sinal na tela do radar (01.2). Está curioso mas apressado — quer entender rápido por quê. Precisa decidir em segundos: "isso merece ação agora ou posso esperar?" A confiança no sistema está em jogo: se a explicação for vaga ou alarmista, perde credibilidade.

**Success Criteria:** Em ≤15 segundos, líder entende por que o sistema destacou esta pessoa e decide: ver perfil completo (→ 01.4) ou registrar cuidado direto (→ 01.5) ou voltar ao radar. A explicação reforça confiança no radar humilde.

**Entry Points:**
- (1) Tap no ParticipantCard expanded/medium na 01.2 (navegação primária)
- (2) Tap em item do ReturnBanner (01.2-R1) expandido
- (3) Deep link `/app/gestao/radar/{participantId}`

**Exit Points:**
- (1) "Ver essa pessoa" → 01.4 Perfil Participante (`/app/gestao/radar/{participantId}/perfil`)
- (2) "Registrar cuidado" → 01.5 Loop Fechado (`/app/gestao/radar/{participantId}/cuidado`) — atalho direto
- (3) Back/swipe → 01.2 Radar (estado preservado)
- (4) Tabs → navegação lateral

**Route Hierarchy:**
- 01.3: `/app/gestao/radar/{participantId}` — detalhe do sinal
- 01.4: `/app/gestao/radar/{participantId}/perfil` — perfil relacional
- 01.5: `/app/gestao/radar/{participantId}/cuidado` — registro de ação

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default (com cuidado)** | Dados ok, sinal ativo, registro anterior existe | Layout completo com seção 2.5 | Todas |
| **Default (sem cuidado)** | Dados ok, sinal ativo, sem registro anterior | Layout sem seção 2.5 (página mais curta) | Todas |
| **Loading** | Primeiro carregamento | Header com nome+pill (dados de navegação). Seções 2-4: skeleton shimmer. | Back, tabs. Botões disabled. |
| **Error (network)** | Fetch falhou, sem cache | Header + card erro "Não foi possível carregar os detalhes" + retry | Back, retry, tabs |
| **Error (network+cache)** | Fetch falhou, cache disponível | Layout normal + banner offline dismissable | Todas (cached) |
| **Error (not found)** | participantId inválido ou não pertence ao líder | Redirect → 01.2 + toast "Participante não encontrado" | — |
| **Signal resolved** | Sinal mudou para 🟢 entre tap e carregamento | Pill 🟢 + mensagem celebratória. "Registrar cuidado" hidden. | Back, ver pessoa, tabs |

**Transitions:**
```
[Loading] → ok, com cuidado → [Default (com cuidado)]
[Loading] → ok, sem cuidado → [Default (sem cuidado)]
[Loading] → ok, sinal resolvido → [Signal resolved]
[Loading] → fail, no cache → [Error network]
[Loading] → fail, cache → [Error network+cache]
[Loading] → not found → [Error not found] → redirect 01.2
[Error network] → retry ok → [Default *]
```

## Validation & Defensive Rules

**Parameter validation:**

| Context | Parameter | Rule | Fallback |
|---------|-----------|------|----------|
| Route | `{participantId}` | UUID v7, pertence ao líder | Redirect 01.2 + toast (mesmo erro para "não existe" e "não pertence" — multi-tenant safe) |
| Navigation | `signalType` | Enum care-urgent/attention | Ausente → fetch backend. Se `care-ok` → Signal resolved |
| Navigation | `groupId` | UUID v7, grupo do líder | Ausente → primeiro grupo do participante |
| Deep link | Auth check | User autenticado | → login → redirect back |

**API data validation:**

| Data | Validation | Fallback |
|------|-----------|----------|
| `participant.name` | String não-vazia | `""` → "Participante" |
| `participant.signalType` | Enum | Desconhecido → `care-ok` + Signal resolved |
| `observedFact` | String não-vazia | `null` → `signal.observed.fallback` |
| `systemLimitation` | String | `null` → `signal.limitation.generic` |
| `lastCareRecord` | Object ou null | `null` → seção 2.5 omitida |
| `lastCareRecord.date` | ISO 8601 | Inválido → omitir data |
| `presenceDots[]` | Array de enum | `[]` → seção Timeline omitida |

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/`). Não indexável.
- **Data fetching:** TanStack Query — `useSignalDetail(participantId)`. Cache-first.
- **Navigation state:** Nome + pill passados via navigation params da 01.2 → header renderiza instantâneo (sem fetch). Dados de detalhe carregam em background.
- **Multi-tenancy:** `tenantId` via AsyncLocalStorage. Validação: participante pertence ao tenant ativo do líder.
- **Performance:** TTI ≤2s. Header imediato (dados de nav), conteúdo com skeleton.
- **Accessibility:** WCAG AA. Cor + ícone na pill. Dots com aria-labels individuais. Legenda visível para screen readers.
