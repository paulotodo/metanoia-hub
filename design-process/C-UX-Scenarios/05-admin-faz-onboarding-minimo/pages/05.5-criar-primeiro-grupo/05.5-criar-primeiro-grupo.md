## Overview

**Page Purpose:** Criar o primeiro grupo da igreja com o mínimo absoluto: nome do grupo, um participante (o próprio admin como teste). 3 campos. Ao salvar, o NFR-X1 está satisfeito: tenant ativo + grupo + participante + radar vivo. É o momento de ativação primária.

**User Situation:** Pastor viu o radar de demonstração (05.4) e está empolgado. Quer criar o grupo rápido e ver os dados reais aparecerem. Está no ritmo — 5 minutos se passaram, restam 5 para completar o NFR-X1. Se o formulário for curto, ele termina. Se for longo, começa a duvidar.

**Success Criteria:** Em ≤120 segundos, pastor preenche nome do grupo, confirma "me adicionar como participante" e toca "Criar grupo". Grupo criado, dados de demonstração mesclados, pastor redirecionado para o painel admin com radar vivo. NFR-X1 cumprido. Evento `tenant.activation.primary` disparado.

**Entry Points:**
- (1) "Criar grupo" na 05.4 (caminho primário)
- (2) Sidebar → Grupos → "Novo grupo" (acesso direto)

**Exit Points:**
- (1) "Criar grupo" (form válido) → `/app/admin/` com radar vivo + toast de sucesso
- (2) Back → 05.4 Boas-vindas
- (3) Sidebar → navegação lateral

**Route:** `/app/admin/grupos/novo` — query param `?first=true` quando vindo da 05.4 (ativa copy de primeira vez).

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default (first-run)** | `?first=true` | Title "Crie seu primeiro grupo" + descrição + selfAdd checked | Preencher, criar |

**Post-success flow:**
```
[Submit success] → redirect `/app/admin/` 
  → toast "Grupo criado! Seu radar já está funcionando."
  → radar agora mistura dados demo + grupo real
  → NFR-X1 ✅ completo
```

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/`).
- **Group creation:** POST `/api/v1/groups` com body `{ name, description?, dayOfWeek?, timeOfDay?, addSelfAsParticipant }`. Response 201 → `{ data: { groupId } }`.
- **Self-add:** Se `addSelfAsParticipant: true` → backend cria participant record para o admin user no mesmo grupo. Usa `uuidv7()` para participant ID.
- **Activation event:** Backend verifica `tenant.groups.count`. Se transição 0→1 → emite `tenant.activation.primary` com `{ tenantId, groupId, elapsedMinutes }`. Elapsed calculado desde `tenant.createdAt`.
- **Demo data merge:** Dados de demonstração permanecem visíveis por 7 dias após primeiro grupo real, depois são removidos automaticamente (Story 7.2 lifecycle). Marcados visualmente como "demonstração" no radar.
- **Multi-tenancy:** `tenantId` via AsyncLocalStorage. Grupo criado com `tenant_id` via Prisma extension.
- **Accessibility:** WCAG AA. Auto-focus no primeiro campo. Labels associados. Checkbox com hint via `aria-describedby`.
