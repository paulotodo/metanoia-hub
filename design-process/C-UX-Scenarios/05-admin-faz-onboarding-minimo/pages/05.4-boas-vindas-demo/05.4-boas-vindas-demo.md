## Overview

**Page Purpose:** O momento "wow". Pastor acabou de criar a conta e vê o produto funcionando pela primeira vez — com dados de demonstração carregados (Story 7.2). O radar pastoral aparece vivo, com sinais fictícios que mostram exatamente como vai funcionar com dados reais. A tela de boas-vindas (Story 7.1) acolhe e direciona: "sua igreja está pronta — agora crie seu primeiro grupo".

**User Situation:** Pastor acabou de criar a conta (≈5 min desde o clique no email). Está autenticado pela primeira vez. Espera ansioso: "o que é esse produto, na prática?" Os dados de demonstração respondem essa pergunta antes que ele precise configurar qualquer coisa. É a prova de conceito instantânea.

**Success Criteria:** Em ≤30 segundos, pastor vê o radar pastoral com dados de demonstração e entende: "é assim que vai funcionar com minha igreja". Toca "Criar grupo" com entusiasmo, não com dúvida.

**Entry Points:**
- (1) Redirect automático após criar conta na 05.3 (caminho primário)
- (2) Acesso direto `/app/admin/boas-vindas` (re-visit — disponível até criar primeiro grupo)

**Exit Points:**
- (1) "Criar grupo" → 05.5 Criar Primeiro Grupo
- (2) Navigation sidebar → outras áreas admin (edge case — pastor curioso)

**Route:** `/app/admin/boas-vindas` — rota autenticada, admin only. Disponível até o primeiro grupo ser criado; após, redireciona para `/app/admin/`.

## Reference Materials

**Strategic Foundation:**
- Epic 7 Story 7.1 — Tela de boas-vindas pós-login
- Epic 7 Story 7.2 — Dados de demonstração do radar

**Design Constraints:**
- **Dados de demonstração obrigatórios:** o pastor PRECISA ver o radar funcionando antes de criar qualquer coisa. Sem dados demo → "tela vazia" mata conversão.
- **NFR-X1 compliance:** esta tela é ~5 min into the flow. Faltam criar grupo + participante para completar NFR-X1 em ≤10 min.
- **Desktop-first:** layout com sidebar admin + área de conteúdo principal
- **Zero tutorial obrigatório:** dados demo falam por si. Sem vídeo, sem modal, sem tour forçado.
- Glossário banido: tenant, provisionar, dashboard, onboarding, demo data, seed

## Technical Notes

- **Rendering:** CSR (autenticada, `/app/`).
- **Demo data:** Carregado via `useWelcomeDemoData()`. Dados de demonstração são tenant-scoped (Story 7.2) — cada tenant recebe uma cópia isolada. Removidos automaticamente quando primeiro grupo real é criado.
- **Route guard:** Middleware verifica `tenant.groups.count`. Se >0 → redirect `/app/admin/`.
- **Sidebar:** Componente AdminSidebar — usado em todas as telas `/app/admin/*`.
- **Performance:** TTI ≤2s. Demo data é leve (3 records). Skeleton desnecessário.
- **Accessibility:** WCAG AA. Sidebar com `nav` landmark. Demo cards com `aria-label` indicando demonstração. CTA com focus visível.
