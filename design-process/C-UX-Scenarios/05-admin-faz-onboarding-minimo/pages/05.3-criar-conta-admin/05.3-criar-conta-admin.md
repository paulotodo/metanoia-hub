## Overview

**Page Purpose:** Criar a conta do admin e o tenant da igreja em um único formulário. 4 campos: nome, email, senha (ou Google OAuth), nome da igreja. Nada mais. Resultado: sessão ativa, tenant criado com RLS, role Admin Tenant atribuído via Keycloak.

**User Situation:** Pastor aceitou os termos. Está confiante até aqui — o processo é simples. Espera que criar a conta seja igualmente rápido. Se aparecerem 15 campos, ele vai suspirar. Se aparecerem 4, ele sorri e preenche.

**Success Criteria:** Em ≤90 segundos, pastor preenche os 4 campos (ou usa Google OAuth para 2) e toca "Criar conta". A conta é criada, o tenant da igreja provisioned, e ele é redirecionado para a 05.4 já autenticado.

**Entry Points:**
- (1) "Continuar" na 05.2 (caminho primário)

**Exit Points:**
- (1) "Criar conta" (formulário válido) → 05.4 Boas-vindas + Demo
- (2) "Continuar com Google" (OAuth) → 05.4 (pula email/senha)
- (3) Back → 05.2

**Route:** `/convite/{token}/criar-conta`

---

## Reference Materials

**Design Constraints:**
- **Mínimo absoluto de campos:** nome + email + senha + nome da igreja. Tudo mais é Release 1b (wizard step 1/2)
- **Google OAuth disponível:** Stories 2.1/2.2 mergeadas. OAuth pula email+senha, mantém nome+igreja.
- **Keycloak backend:** conta criada no Keycloak, role Admin Tenant atribuído, tenant criado com RLS
- NFRs: TTI ≤2s, WCAG AA
- Glossário banido: tenant, provisionar, admin, role (user-facing)

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default (email/senha)** | Entrada normal | 4 campos + botão | Preencher, submit |
| **Default (pós-OAuth)** | Google OAuth sucesso | Nome preenchido+disabled, email oculto, senha oculta, igreja com foco | Preencher igreja, submit |
| **Validation errors** | Submit com erros | Campos com borda destructive + mensagens | Corrigir, submit |
| **Loading** | Criando conta | Botão com spinner, campos disabled | Nenhuma |
| **Error (duplicate email)** | Email já existe | Inline error no campo email + sugestão login | Corrigir email ou ir para login |
| **Error (network)** | Falha de rede | Toast "Erro ao criar conta" | Retry |
| **Error (OAuth failed)** | Google OAuth falhou | Toast "Não foi possível conectar com Google" + form email/senha visível | Usar email/senha, retry OAuth |

## Technical Notes

- **Rendering:** SSR (hydrated) — rota pública, continuação do token flow.
- **Account creation:** POST `/api/v1/invites/{token}/create-account` com body `{ name, email, password?, oauthProvider?, churchName }`. Response 201 → `{ data: { userId, tenantId, sessionToken } }`.
- **Backend flow:** Keycloak cria user + atribui role `Admin Tenant` → Prisma cria tenant (RLS seed) → Session criada → redirect 05.4 com sessão ativa.
- **Google OAuth:** Flow popup. Retorna `{ name, email, googleId }`. Backend liga Google account ao Keycloak user.
- **Password:** Hash via Keycloak (bcrypt). Nunca armazenado no app DB.
- **Tenant creation:** `tenant_id` gerado com `uuidv7()`. RLS policy criada. Nome da igreja = `tenant.display_name`.
- **Accessibility:** WCAG AA. Labels associados. Password toggle com aria-label. Focus management no OAuth callback. Error messages via `aria-describedby`.
