## Não-dependência de cor

- [x] CHK014 - O requisito de badge de engajamento por texto+ícone (não só cor) está especificado? [Completude, Spec §FR-08] {auto} — Resolvido: FR-08 "badges devem comunicar o nível por texto + ícone (não apenas cor)".
- [x] CHK015 - O requisito de ícone de status de presença acompanhado de texto legível está expresso? [Completude, Spec §FR-08] {auto} — Resolvido: FR-08 "ícones de status acompanhados de texto legível".
- [x] CHK016 - Existe critério de sucesso verificável (auditoria automatizada + inspeção manual) para não-dependência de cor? [Mensurabilidade, Spec §SC-06] {auto} — Resolvido: SC-06 "verificável por auditoria automatizada e inspeção manual".

## Contraste

- [x] CHK017 - O requisito de contraste mínimo está quantificado com razão específica (4.5:1 WCAG AA)? [Clareza, Spec §FR-08] {auto} — Resolvido: FR-08 "contraste mínimo 4.5:1 (WCAG AA)" para token de texto secundário.
- [ ] CHK018 - O contraste mínimo 4.5:1 cobre TODOS os pares texto/fundo da página, ou apenas o token de texto secundário citado? [Ambiguity, Spec §FR-08] {auto} — [Ambiguity]: FR-08 só nomeia o "token de cor para texto secundário"; badges/ícones/CTA não têm alvo de contraste explícito. Recomendado clarificar escopo (todos os componentes vs. só secundário) — encaminhar a /clarify ou tratar como "todos os elementos de texto" no create-tasks.

## Gráficos / dados não-textuais

- [x] CHK019 - O requisito de aria-label descritivo para gráficos/sparklines está expresso? [Completude, Spec §FR-08] {auto} — Resolvido: FR-08 "Gráficos/sparklines devem ter aria-label descritivo".
- [x] CHK020 - O requisito de equivalente em tabela acessível para os gráficos está expresso (não só aria-label)? [Completude, Spec §FR-08] {auto} — Resolvido: FR-08 "e equivalente em tabela acessível".
- [ ] CHK021 - O equivalente acessível do gráfico de tendência (FR-10, nice-to-have) é obrigatório quando o gráfico está presente, ou opcional junto com ele? [Ambiguity, Spec §FR-08 ↔ §FR-10] {auto} — [Ambiguity]: FR-10 marca a tendência como opcional; FR-08 exige tabela acessível para "gráficos/sparklines". Se a tendência renderizar, a tabela equivalente deve ser obrigatória. Encaminhar a /clarify ou fixar no create-tasks ("se FR-10 ativo → tabela equivalente obrigatória").

## Contexto textual de métricas

- [x] CHK022 - O requisito de contexto textual para o score médio (além do número) está expresso? [Completude, Spec §FR-08] {auto} — Resolvido: FR-08 "Score médio de engajamento deve ter contexto textual além do número".

## Degradação graciosa (CTA pastoral)

- [x] CHK023 - O requisito de omitir/desabilitar o CTA "Cuidar" sem quebrar a interface quando o módulo pastoral está ausente está especificado? [Cobertura, Spec §FR-09] {auto} — Resolvido: FR-09 "CTA deve ser omitido ou desabilitado graciosamente — sem quebrar a interface".
- [ ] CHK024 - O estado "desabilitado" do CTA pastoral tem requisito de acessibilidade próprio (aria-disabled, foco, anúncio para leitor de tela)? [Gap, Spec §FR-09] {auto} — [Gap]: FR-09 menciona "desabilitado graciosamente" mas não especifica o tratamento a11y do estado disabled (aria-disabled vs. remoção do tab order, anúncio). Vira tarefa de requisito no create-tasks.
