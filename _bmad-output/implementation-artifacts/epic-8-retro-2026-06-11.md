## 3. Desafios e armadilhas recorrentes (⚠️)

**Charlie (Senior Dev):** "O boilerplate de RLS spec no Prisma v7 nos mordeu repetidamente — em 6-x e de novo em 8-x. O padrão que funciona já é conhecido (adapter `PrismaPg({connectionString: DATABASE_APP_URL})`, UUIDs fixos hex, users globais sem role, `group_members` sem `updated_at`, cadeia FK tenant→trail→module→lesson em `beforeAll`/`afterAll`, `beforeEach` limpando só mutável), mas re-derivamos a cada story."

**Dana (QA):** "Invariantes de schema quebraram CI várias vezes: CASCADE FK→users, colunas NOT NULL (day_of_week/time/recurrence/updated_at), CHECK de `presence_type`. E os flakes crônicos: `reflections.rls-spec.ts` (FK P2003), E2E `registry-1.docker.io deadline`, cache-miss turbo/prisma — todos resolvidos só com `gh run rerun`."

**Elena (Junior Dev):** "Os artifacts tinham drift de campos — `Lesson` não tem `title`/`description`, só `name`/`tags`. A RECONCILIACAO-EPIC8-W1b3 teve que mapear para as colunas reais antes do 8-8."

**Bob (SM):** "E as sessões caíram no meio da 8-8 e 8-9 — lock stale do feature-00c. A recuperação (remover `.lock` órfão + resume) virou rotina."

**Charlie (Senior Dev):** _sério_ "Mas o achado de processo mais importante foi a 8-10: o orquestrador feature-00c **commitou e deu push direto em `dev`, sem PR**. Como o `ci.yml` só dispara em `pull_request`, o CI **nunca rodou** — e o código tinha 2 erros de lint (`--max-warnings 0`) e 1 violação jest-axe (`aria-prohibited-attr`) que teriam barrado o merge. Foi pego só porque auditamos o git manualmente depois do 'concluido'."

**Paulo (Project Lead):** _decisão_ "Recuperar via PR limpo: reset `dev`→`84c5e22`, mover o trabalho para feature-branch, corrigir, abrir PR, CI verde, squash-merge. Foi o que fizemos (PR #134, `1ce3bb0`)."

## 4. Insights-chave

1. **O sumário do subagente não é prova.** "Guardrails seguidos" no relatório do feature-00c não equivale a build/lint/teste verdes. Auditar o git real é obrigatório antes de declarar done.
2. **Push direto em `dev` é uma brecha estrutural**: `ci.yml` só roda em `pull_request`. Sem branch protection, qualquer commit direto escapa de todo o quality gate.
3. **RECONCILIACAO pré-flight por wave funciona** — evitou recriar base já entregue e mapeou drifts de campo antes da implementação.
4. **O RLS spec Prisma v7 é dívida de fricção repetida** — candidato nº1 a virar helper/factory compartilhado.

## 6. Preparação para o Epic 9 (Privacidade, LGPD & Compliance)

**Próximo épico:** Exportação de dados pessoais (portabilidade), exclusão (eliminação), base legal por operação, e audit log imutável (interceptor append-only).

**Reúso direto do Epic 8:**
- Padrão **BullMQ job + polling** (8-7 reports) → `queue:privacy-export` + `GET /privacy/export/:jobId`.
- **Signed URL MinIO** (8-2 storage) → entrega do arquivo de export.
- Contrato **202 + jobId** já consolidado.

### 🚨 Achado significativo — dependência não atendida

A Story 9.1 assume que **cada módulo expõe `exportUserData(userId, tenantId)`** (coleta respeitando fronteiras de módulo, NÃO query direta às tabelas). O **Content module (Epic 8) não criou esse método** — precisa exportar trail progress + lesson progress. Há também um teste de completude que FALHA se uma tabela nova não tiver o `exportUserData()` correspondente.

**Recomendação:** antes de iniciar o Epic 9, adicionar `exportUserData()` aos services tocados pelo Epic 8 (content/progress) — seja como pré-requisito da 9.1, seja como story de preparação. Mesmo gap aplica-se a Radar (Epic 6) e Meetings (Epic 5).
